# W03 품질 이슈·공급 복구 운영 시스템

AX인재전쟁 온라인 삼일PwC 출제 회차(2026.11)에 개인으로 참가해 만든 업무 운영 시스템입니다.
화장품 제품 PL-02에 피부 트러블 클레임과 언론 보도가 겹친 상황에서, **클레임 접수 → 회수 대상 판정 → 품질위원회 의결 → 재공급 계획**까지를 하나의 흐름으로 잇습니다.

- 배포: https://ax-rgav.axhub.app (로그인 없음, 심사 기간 운영)
- 설계 문서: [`DESIGN.md`](DESIGN.md) — 규칙 10개(R1~R10), 직접 세운 가정 32개(A-1~A-32), AI와 사람의 역할, BPMN 변경점

## 무엇을 하나
| 단계 | 하는 일 |
|---|---|
| 판정 | 클레임이 들어오면 배치별 확정 불량률을 생산량·출하량 두 분모로 즉시 다시 계산하고, 하나라도 10% 이상이면 회수대상으로 판정 |
| 상신 | 승인 요청 한 줄, 근거 수치, 영향 고객, 같은 원료 로트 배치, **승인 시 예상 공급 영향을 의결 전에** 보여 줌 |
| 의결 | 품질위원회가 배치별로 승인·거절하고 사유를 남김. 처리 목표는 상신 후 1영업일, 넘기면 지연으로 표시 |
| 실행 | 회수요청·출하보류 상태 변경, 고객 통지·재고 격리·재공급 요청·원인 조사 작업 생성, 모든 변경 이력 기록 |
| 재공급 | 필요량 ÷ 라인 여유로 판정하고 보유량 회신 → 납기 연기 → 증설 순서로 대안 적용 |
| 로트 역추적 | 회수 배치와 같은 원료 로트를 쓴 배치를 찾아 출하 전 추가검사로 묶고, 재공급 계산에서 제외 |

## 대회 데이터 기준 결과
- 회수대상 2개 배치: B-02-2602-01 11.87%·12.27%, B-02-2603-01 11.59%·12.11% (생산·출하 기준)
- 재공급 필요량 상한 299,653EA, 라인 여유 58,484EA → 필요량이 여유의 5.12배라 '대안필요'
- 로트 역추적으로 같은 로트 재고 13,696EA를 출하 전 추가검사로 묶음
- 과잉 대응 비교: 같은 로트 전부 회수 시 약 2배, 2026년 생산분 전부 회수 시 약 9.1배 물량 (추정치)
- 자동 테스트 195개

## AI와 사람의 역할
- **AI:** 상신 요약 문장과 부서별 조치 문장, 자유 형식 회신의 항목 정리만 맡습니다. 입력은 규칙 엔진의 계산값뿐이고, 문장 속 숫자가 계산값과 다르거나 의결 전에 결정된 것처럼 읽히면 다시 생성합니다. 실패하면 사람이 직접 쓰는 경로로 넘어갑니다.
- **규칙 엔진:** 불량률 계산, 판정, 재공급 계산, 상태 변경.
- **사람:** 위원회 의결과 사유, 회신 반영, 정정, 재공급 대안 선택과 부서별 승인.

## 만든 방식
업무 규칙과 판단 기준을 정하고 결과를 검증하는 일은 제가 했고, 코드는 Claude Code로 작성했습니다.
Python 3.12 · FastAPI · Jinja2 · SQLite · Pydantic · Gemini API · pytest

## 포함하지 않은 것
대회가 배포한 문제 자료와 원본 데이터(`01_참가자_배포용/`)는 재배포하지 않습니다. 실행하려면 대회 자료를 받아 같은 위치에 두어야 합니다.

## 실행 방법

1. Python 3.12 이상에서 의존성을 설치해요.
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. AI 설정(선택). 키가 없어도 앱은 동작하고, AI 단계는 '요약 실패 - 수동 작성' / 사람 구조화 폼 경로로 넘어가요.

   | 환경변수 | 값 | 설명 |
   |---|---|---|
   | `AI_PROVIDER` | `gemini` 또는 비움 | `gemini`면 Gemini, 비우면 Anthropic Claude |
   | `GEMINI_API_KEY` | Gemini API 키 | `AI_PROVIDER=gemini`일 때 필요 |
   | `GEMINI_MODEL` | 기본 `gemini-3.5-flash-lite` | 무료 등급 Flash-Lite. 다른 Flash 모델로 바꿀 수 있어요 |
   | `W03_DB` | 기본 임시 폴더 | 실행 상태 DB 위치. 빈 DB로 시작하면 시작 상태(업무일 2026-07-01 · 판정 · 회수상신 #1, AI 요약)를 자동으로 만들어요 |
   | `W03_AUTOSEED` | 기본 `1` | `0`이면 시작 상태 자동 생성을 끄고 빈 상태로 시작해요(테스트용) |
   | `ANTHROPIC_API_KEY` | Anthropic API 키 | Claude(`claude-opus-5-5`)를 쓸 때 필요 |

   키 값은 셸 환경변수로만 넣고 파일·저장소에 남기지 마세요. Gemini 무료 등급은 503(일시적 과부하)이 잦아서 503에 한해 최대 2회 자동 재시도하고(95초 안에서), 그래도 실패하면 사유와 재시도 횟수를 화면에 보여 주고 수동 경로로 넘어가요. 429(한도 초과)도 같은 수동 경로예요.
3. 대회 원본 데이터를 `01_참가자_배포용/04_원본데이터/`에 둡니다(이 저장소에는 포함하지 않음).
4. 실행: `uvicorn main:app --host 127.0.0.1 --port 3000` → http://127.0.0.1:3000
   원본 CSV(`01_참가자_배포용/04_원본데이터/`)는 읽기만 하고, 실행 상태 DB는 임시 폴더에 만들어요(`W03_DB`로 바꿀 수 있어요).
5. 시연: 대시보드의 '판정 실행' → '회수대상 2건 상신'(AI 요약) 또는 시연 프리셋(정정·납기 연기·로트 역추적·회신 구조화)을 눌러요.
   새 클레임은 '0. 클레임 접수'(`/claims`)에서 넣으면 바로 재판정돼요(이미 회수의결된 배치면 새 상신 없이 '회수 범위 확인' 작업). 언론 보도는 '외부 정보 접수'(`/external`)로 넣으면 판단을 재검토하되 R5에 따라 판정은 유지돼요. 배치별 연결은 `/trace/<배치ID>`, 의결 전 공급 영향은 상신 화면 의결 버튼 위에 있어요.
   첫 화면 맨 위 '결정 대기'가 지금 사람이 판단할 일을 급한 순서로 보여 주고, '업무일 → 다음 영업일'로 하루씩 넘기면(A05 월~금) 기한 지난 작업이 '지연'으로 올라와요. 위원회 의결은 상신 후 1영업일(A-32)이 지나면 '의결 지연 N영업일'로 맨 위에 올라와요.
   개선 효과(추정치·비교 기준·가정)와 추가 데이터 추적성 점검은 `/effects`, 규칙 10개(R1~R10)·가정 32개(A-1~A-32)의 뜻과 출처 성격은 `/glossary`에 있어요. 시연 프리셋은 대시보드 맨 아래 접힌 영역에 있어요.
6. 테스트: `pip install pytest httpx` 후 `python -m pytest -q`. AI 호출은 가짜 응답으로 대체돼 키·비용이 필요 없어요.

### 실행 제약
- **실행 DB는 임시 폴더예요.** 앱이 재시작되면(재배포·서버 재시작 포함) 화면에서 입력한 의결·회신·클레임 접수·정정·업무일 진행이 모두 사라지고,
  시작 상태(업무일 2026-07-01 · 판정 완료 · 회수상신 #1, AI 요약)로 돌아가요. 빈 화면이 나오지는 않아요.
- 시작 상태의 상신 요약은 재시작할 때마다 AI가 새로 만들어서 문장이 이전과 다를 수 있어요. AI 호출이 실패하면 '요약 실패 - 수동 작성'과 사유가 표시돼요.
- 입력을 보존하려면 `W03_DB`를 재시작해도 지워지지 않는 경로로 지정해야 해요(배포 환경은 임시 폴더 그대로예요).
